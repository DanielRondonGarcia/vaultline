# On-demand Windows Worker Self-update
Outcome: Add an explicit `vaultline-worker update` command that fetches the latest stable Windows MSI, verifies its same-release SHA256SUMS entry, stops the worker service, and completes the upgrade visibly in the invoking console through a stable launcher.
Scope: Windows MSI, stable launcher/worker split, service registration, CLI dispatch, and release verification for Server 2022; no background updater or Linux package-manager changes.

## Specs
1. S1: “agregar funcionalidad al cli de vaultline de auto update”; clarification: “pues de auto me refiero a el mismo, no que lo haga solo. y que se pueda por comando” — the worker updates itself only when the user invokes the CLI command; do not add a background updater.
2. S2: “Checksum y GitHub Releases” — verify the downloaded MSI against the SHA256SUMS asset from the same stable GitHub release before invoking installation.
3. S3: “genera un release para probar” — create a release after implementing and verifying the command and the Restic/rclone fix.
4. S4: “peero debe de detener el servicio para poder instalarlo”; clarification: “por eso, el mismo update debe de ser capaz de hacerlo, haz el ajuste” — `vaultline-worker update` itself must stop and wait for `VaultlineWorker` to stop before starting the MSI.
5. S5: “pero todo lo quiero inline, nada de que started, no, ahi mismo en la consola, ver todo el proceso de actualización” — `vaultline-worker update` must keep the update visibly running in the invoking console through completion, not return an asynchronous `started` message.
